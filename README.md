# acme-policy

Central policy repo of the Acme frontend ecosystem (FE Blueprint §3.3: the policy repo is always separate, so the
verifier stays outside the control of a PR's author — Standard §7.15, CORE-VER-05).

Every active check declares violating and conforming fixtures (or a proof test) in `registry/checks.yaml`;
`test/registry-proof.test.mjs` proves each one fires on its violations and stays silent on clean input (mutation proof,
FE §8.2 rule 1). `validate-self` enforces the registry rules (Standard target modes, pilot mode, lifecycle, fixtures).
Run everything with `pnpm test`.

## Usage

```bash
pnpm install && pnpm test        # installs the kit too (pnpm workspace: presets)
node bin/acme-policy.mjs sync --repo ../acme-frontend [--check]
node bin/acme-policy.mjs run --repo ../acme-frontend --command verify:fast
node bin/acme-policy.mjs sod --input checks/policy-sod/fixtures/medium-requester-self-approves.json
pnpm showcase                     # all scenarios; --only SC-03 for one; --json for machine-readable output
```

`run` exits 1 when a blocking check FAILs **or a required blocking check is `NOT_ASSESSED`**, and 2 on any `ERROR`.
With a non-local executor (`FACTORY_EXECUTOR=ci`), build-tool caches are disabled so results are never replayed.

Exit codes (FE §7.6): `0` pass, `1` check failure, `2` infrastructure error (`ERROR`).
